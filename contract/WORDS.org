#+TITLE: gforth-inspect words: the interface
#+STARTUP: showall

The words =inspect.fs= defines for use, their stack effects and the text
they print. The log they write is specified in [[file:stacks-log.org][stacks-log.org]] and
[[file:stacks-log.schema.json][stacks-log.schema.json]]. Every other word in =inspect.fs= is internal and
may change in any release.

* Supported gforth

| gforth | engines                          | status                                                                 |
|--------+----------------------------------+------------------------------------------------------------------------|
| 0.7.3, 64-bit | =gforth=, =gforth-fast=, =gforth-itc= | supported and tested: every word below, every release                  |
| 0.7.3, 32-bit | —                                | not supported: load fails with =gforth-inspect requires a 64-bit gforth 0.7.3; this one has 4-byte cells= (the log-dir hash needs 64-bit cells) |
| < 0.7.3 | —                               | not supported: load fails with the dependency message |
| 1.0.x  | —                                | not supported: load fails with a dependency message. Since 0.3.0 the first lines of =inspect.fs=, before any definition, print =gforth-inspect requires gforth 0.7.3 (>= 0.7.3, < 1.0); this is gforth 1.0.1= on stderr and =-1 throw=: =gforth inspect.fs= exits 1 and =include inspect.fs= throws. Without that check it would stop at an undefined word: three 0.7.3 internals it uses (=interpret1=, =handler-intro,=, =.debugline-stderr=) are gone in 1.0.0 and 1.0.1 |
| other 0.x | —                              | not tested: one line on stderr (=gforth-inspect: tested on gforth 0.7.3 only; this is gforth 0.7.9=), then it loads on as far as it can |

=inspect.fs= uses only words present in 0.7.3. It uses no gforth 1.0
words (={: :}=, =[: ;]=, =[{:=).

* Guarantees

- No word below changes =BASE= or the float =PRECISION=.
- A word that reads a stack leaves every stack bit-identical: data, float,
  return, control-flow.
- The log is always decimal, whatever =BASE= is. In the text, depths
  (=<n>=), offsets (=+n=) and =>in== are decimal and addresses print as =$= hex;
  stack values and plain return-stack cells follow =BASE=, as =.s= does
  (=hex 1F .stacks= prints =data   <1> 1F=).
- Loading =inspect.fs= twice redefines its words. Load it once
  (=require inspect.fs=, with =fpath+ dir= to find it).

* Words

| word              | stack effect                 | immediacy               | does                                                                              |
|-------------------+------------------------------+-------------------------+-----------------------------------------------------------------------------------|
| =.stacks=         | ( -- )                       |                         | prints the data, float and return stacks and the input line (format below); with =log-on=, writes one =snapshot= record |
| =.rs=             | ( -- )                       |                         | prints the return stack of the caller, top first; stops at the text interpreter unless =rs-full= is on |
| =.input=          | ( -- )                       |                         | prints the current source: file:line, =>in=, the line, a caret under =>IN=           |
| =.cs=             | ( -- )                       | immediate               | inside a definition: prints the compile-time control-flow stack                  |
| =~~~=             | compile: ( -- ) run: ( -- )  | immediate, compile-only | at run time, prints =file:line in word= and the stacks, with the return stack taken at the =~~~=; with =log-on=, writes a =snapshot= record with =where= and =src= |
| =all-~~=          | ( -- )                       |                         | makes plain =~~= print what =~~~= prints (and log, with =log-on=)                   |
| =rs-full=         | ( -- a-addr )                | variable                | =rs-full on=: =.rs= and =.stacks= include the interpreter's frames                    |
| =fclearstack=     | ( F: r1 ... rn -- )          |                         | empties the float stack                                                          |
| =dbg-fix=         | ( -- )                       |                         | makes stock =dbg= step in every engine, =n= (nest) included; =dbg= of a DEFER or DOES> word nests into its target |
| =dbg+=            | ( -- )                       |                         | =dbg-fix=, plus a =D: F: R:= line before every step                                    |
| =log-on=          | ( -- )                       |                         | opens the log (path below) for appending and writes a =hello= record              |
| =log-off=         | ( -- )                       |                         | closes the log; later snapshots are printed, not logged                           |
| =log-where=       | ( -- )                       |                         | prints the log's path on its own line                                            |
| =log-id=          | ( c-addr u -- )              |                         | tags the following snapshots with ="id"=, at most 63 bytes; =s" " log-id= clears it |
| =inspect-version= | ( -- c-addr u )              |                         | the release version, ="X.Y.Z"=, the same as the file's first line                   |
| =contract-version= | ( -- c-addr u )             |                         | the log contract, ="MAJOR.MINOR"=, the same as =hello.contract=                       |

Log path: =<dir>/stacks.jsonl=. =<dir>= is =$GFORTH_INSPECT_LOG_DIR= when that
variable is set and non-empty; else the =GFORTH_INSPECT_LOG_DIR== line of the
project's =.env=; else, per project and worktree,
=${XDG_STATE_HOME:-~/.local/state}/gforth-inspect/<owner>/<repo>/<worktree>=
(=.../gforth-inspect= itself when the current directory cannot be read),
from the process's current directory, never =$PWD=. The exact rule is
[[file:stacks-log.org][stacks-log.org]], "Files".

* Output formats

Text goes to stdout, except =~~~= and =~~= (after =all-~~=), which write all of
their output to stderr, as stock =~~= does. =$ADDR= below stands for an address
printed in hex, which differs from run to run.

** =.stacks=

#+begin_example
data   <3> 1 2 3
float  <1> 1.500000000000E0
return <R:27> top first
  ... interpreter (rs-full on to see it)
input  *OS command line*:-1 >in=19
1 2 3 1.5e .stacks bye
                   ^
#+end_example

| line      | format                                                                  |
|-----------+-------------------------------------------------------------------------|
| =data=     | =data   <n> x1 ... xn=, bottom first; =<n>= is the depth                    |
| =float=    | =float  <n> r1 ... rn=, as =f.s= prints them (rounded: the log is exact)     |
| =return=   | =return <R:n> top first=, then one line per frame (see =.rs=)               |
| =input=    | =input  file:line >in=n=, then the line, then a caret line under =>IN=        |

The =data= and =float= lines are for reading, not parsing. Read the log for
values.

** =.rs=

#+begin_example
<R:29> top first
  $ADDR = outer +32
  ... interpreter (rs-full on to see it)
#+end_example

Every cell prints as =$HEX= followed by one of:

| form                | when                                                    |
|---------------------+---------------------------------------------------------|
| = = word +offset=   | the cell is a return address inside a colon definition (offset in decimal bytes) |
| = (stack pointer)=  | the cell points into a stack                            |
| = = value=          | anything else; the value follows =BASE= (=5 >r .rs= prints =$5 = 5=) |

With =rs-full on= the interpreter's frames follow in the same forms.

** =.input=

#+begin_example
*OS command line*:-1 >in=7
.input bye
       ^
#+end_example

The file is =*OS command line*= with line =-1= for =-e= text.

** =~~~= (and =~~= after =all-~~=)

#+begin_example
demo.fs:1 in avg
data   <1> 30
float  <0>
return <R:28> top first
  ... interpreter (rs-full on to see it)
input  *OS command line*:-1 >in=10
10 20 avg . bye
          ^
#+end_example

The first line names the place in the source. =~~~= prints =file:line in word=.
=~~= after =all-~~= prints =file:line: in word= (a colon after the line, as
stock =~~= does), and code typed with =-e= gives =*somewhere*:-1: in word=.

** =.cs=

#+begin_example
CS: here=$ADDR
  dest $ADDR  (0 cells back)
  orig (live) $ADDR  (1 cells back) | colon-sys
#+end_example

One line per control-flow item, top first: its kind (=dest=, =orig=,
=do-dest=), its address and how far back from =here= it points.

** =dbg+=

#+begin_example
D: <1> 3  F: <0> R: -
$ADDR $ADDR dup            ->
D: <2> 3 3  F: <0> R: -
#+end_example

=D:= is the data stack, =F:= the float stack, and =R:= the colon words on the
return stack (callers of the word being stepped), or =-= when there are
none. Each =->= waits for a key (stock 0.7.3 =debug.fs=):

| key       | does                                        |
|-----------+---------------------------------------------|
| Enter, or any key not below | one step                  |
| =n=       | nest into the word about to run             |
| =u=       | unnest: run to the end of the current word  |
| =d=       | done: run to the end without stopping       |
| =s=, =a=  | stop: leave the debugger (=-128 throw=)      |
| =?=       | list the keys                               |

A word =dbg= cannot step into is run and reported as =stepped over=; a
defer chain longer than 16 hops is reported and not run.

** =log-where=

Prints an empty line, then the log's path as =log-on= would open it now:
relative when =GFORTH_INSPECT_LOG_DIR= (or the =.env= value) is relative.
Without either, run from a checkout of =acme/widget= on branch =main=, it
prints =$HOME/.local/state/gforth-inspect/acme/widget/main/stacks.jsonl=
with =$HOME= expanded.

* Versioning of this interface

The release version (=inspect-version=) moves like this for the words:
removing or renaming a word, or changing its stack effect, is MAJOR;
adding a word is MINOR. The text formats are for people: a change in
spacing or wording is PATCH, and consumers read the log, never the text,
for data. The log has its own contract version (=contract-version=), with
its rules in [[file:stacks-log.org][stacks-log.org]].

#+TITLE: 001 stacks-roundtrip: non-interference and faithfulness
#+DATE: 2026-11-21
#+STARTUP: showall

* Hypothesis

These hold for any data stack (depth 0 to 20, any cell value including
=min-n= / =max-n=) and any float stack (depth 0 to 8, including =-0e=,
=±inf=, =nan=, subnormals and 17-digit values), in each of three code paths
(=.stacks= at the interpreter, =~~~= inside a colon definition, and =~~=
after =all-~~=), with =log-on=, in each of =gforth=, =gforth-fast= and
=gforth-itc=:

- P1 (non-interference) :: after the inspector word runs, both stacks are
  bit-identical to before. Read the stacks as raw cells (=depth= / =pick=
  printed with =hex u.=, and float bits via =fp@= plus an offset and =@=),
  never through =.s= or =f.s=.
- P2 (faithfulness) :: the snapshot record's =data= equals the independent
  read of the data stack. =float= equals the read's values exactly, with
  each non-finite value as =null=. Every line in =stacks.jsonl= validates
  against =contract/stacks-log.schema.json=.

* Prediction (written before the first run)

P1 holds. P2 is refuted on floats. =json-f= prints through =fs.= with 15
significant digits, which drops the sign of =-0e= (seen once by hand,
=.meta/findings-2026-11-21.org=) and does not round-trip 17-digit values.

* Gate

All runs go through =gmake -C pbt check=. A result counts only if it came
from a committed test and its log line names the inspect.fs provenance.

1. *Volume.* At least 300 Hypothesis examples per (path, engine) pair: 9
   pairs. Batch examples into one gforth process where possible. Report
   the wall time.
2. *P1.* Refuted by any failure. A failure is reported as the shrunk case
   plus a one-line =gforth inspect.fs -e '...'= reproducer.
3. *P2.* Reported per field (=data=, =float=, schema) and per path. A float
   mismatch is classified as sign, precision or non-finite.
4. *Calibration.* =pbt/calibrate/001-*.sh= runs the tests against planted
   faults and must go red on each: (a) =.stacks= leaves an extra cell on the
   data stack, which red P1; (b) =~~~= drops one float, which reds P1; (c)
   =json-data= emits the stack in reverse order, which reds P2. Check that
   each red is the failure you expected.

Out of scope: escaping (002), the return-stack contents beyond schema shape,
and =dbg=.

** 2026-11-21 harness notes (before any gated run)

- Test: =pbt/test_001_stacks_roundtrip.py=. Properties are separate tests,
  so a red P2 float does not cut P1's example count: =test_p1_noninterference=,
  =test_p2_data=, =test_p2_float=, =test_p2_schema=, each parametrized over
  path (=dotstacks= = =.stacks= at the interpreter, =tilde3= = =~~~= in a
  colon definition, =tilde2all= = plain =~~= after =all-~~=) x engine. Plus
  =test_p2_float_corpus=: a fixed list of 20 edge floats, so every mismatch
  class is counted, not only the first one Hypothesis shrinks to.
- One Hypothesis example is a batch of 1 to 12 cases run in one gforth
  process; data depth 0..20 of full-range 64-bit cells, float depth 0..8
  built from bit patterns in Forth (=$bits fbits ! fbits f@=), drawn from
  -0, +-inf, quiet / negative / signalling NaN, subnormals, DBL_MAX,
  17-digit values, any binary64, and any 64-bit pattern.
- The independent read is raw: =depth= / =i pick= / =hex u.=, and
  =fp@ i floats + @ hex u.=. Layout checked by hand in all three engines:
  64-bit cells and floats, =fp@= is the top float and the bottom is at
  higher addresses; NaN payloads survive =f@= and the read.
  For =tilde3= / =tilde2all= the read runs inside the colon definition,
  immediately before and after the inspector word.
- Mismatch classes: =sign= (same magnitude, other sign; in practice -0e),
  =precision= (finite, different value), =non-finite= (null where a number
  was due, a number where null was due, or a finite value whose literal
  decodes to inf).
- Seed: =PBT_SEED=; when unset one is drawn and printed in the summary
  (=001: inspect.fs ... seed N=). =database=None= so runs replay exactly.
- =where= / =src= are not asserted (issue #2: =~~= under =all-~~= logs them
  as null by design). The summary counts what was observed per path.

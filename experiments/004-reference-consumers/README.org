#+TITLE: 004 reference-consumers: is harden's v0.1.0 candidate a non-breaking change?
#+DATE: 2026-11-21
#+STARTUP: showall

* Hypothesis

The three reference consumers in =RELEASING.org= (a jq one-liner, an editor
checker/dashboard reader, and a mock =GET /stacks= server) are frozen as
written. They give the same output on records produced by inspect.fs at
=18ebe2d= (the import the course runs today) as on records produced by
harden's head (the v0.1.0 candidate), for the same programs. The one
exception is the documented #1 fix (=-0e= keeps its sign, and floats print
with 17 digits). Where #1 makes the output differ, the decoded values are
the same as or closer to the true stack, never further from it. So harden
is a MINOR or PATCH change, not a MAJOR one.

* Prediction (written before the first run)

The hypothesis holds for data, rs, input, where and src. For floats it
holds as "the same or closer", by #1. The new =hello.inspect= key and the
moved default log location are the risks. The key is ignorable. The
location is a contract question: the default changes from
=.../sicpminus/= to =.../gforth-inspect/=, and by the rule in
RELEASING.org that alone is breaking for a consumer that hard-codes the
old path. The course says it will set =GFORTH_INSPECT_LOG_DIR=. Whatever
the run finds, this has to be named in the verdict.

* Gate

1. *Consumers frozen.* =pbt/consumers/= holds the three consumers: a jq
   filter file, a stdlib-only Python mock server that serves the last line
   of the log byte for byte, and a Python reader that does the editor
   checker's job (last line, subset-validate, extract the fields). They
   are committed before the first comparison run.
2. *Differential.* At least 200 generated programs (stacks as in 001,
   input lines as in 002, plus the three snapshot paths) are run under both
   refs. Consumer outputs are compared field by field. Each difference is
   classified: #1 float, ignorable new key, or breaking.
3. *Unknown keys.* Each record gets an injected unknown key at the top
   level and inside =input=. All three consumers must give unchanged
   output.
4. *Calibration.* Each planted breaking change must turn the gate red with
   the right classification: rename =data= to =stack=; split one record
   across two lines; print one integer in hex; change =null= to =0= for
   =nan=; move the log so the default path is empty.
5. Verdict: MAJOR, MINOR or PATCH for harden's head, with the reason.

** 2026-11-21 verdict

1. *Consumers frozen*: met. Committed at 7464fc0, before the first run,
   and not edited since.
2. *Differential*: met for fc283da (431 programs logged; 4912 in the CI
   run). There are no =breaking= differences. Every float difference is
   #1, with the new value equal to the bits =fp@= read. The ~~ =where= /
   =src= difference is #2. =escape-fix= is a class outside the three
   written in the gate. It is reported here rather than folded into one of
   them (see 5).
3. *Unknown keys*: met. All three consumers are unchanged at the top level
   and inside =input=.
4. *Calibration*: met. All 6 plants are red with the right
   classification, and the control is green. The default-path plant in
   particular is caught. *The real fc283da fails the same question for a
   consumer that reads 18ebe2d's default*: with =GFORTH_INSPECT_LOG_DIR=
   unset it writes =.../gforth-inspect/stacks.jsonl=, and
   =.../sicpminus/stacks.jsonl= stays empty. The test records this as a
   strict xfail.
   - Version stop: 18ebe2d is refused (no contract), and fc283da is
     accepted (contract 1.1). 9b92746 was refused like 18ebe2d.
5. *Semver for fc283da*: *MAJOR*, by RELEASING.org read literally.
   "Change the default file location" is in the MAJOR row, and fc283da
   (like 9b92746) changes it. A consumer that relies on the default path
   (=${XDG_STATE_HOME:-~/.local/state}/sicpminus/stacks.jsonl=) with
   =GFORTH_INSPECT_LOG_DIR= unset is broken: it finds no log, or a stale
   one. A consumer that sets =GFORTH_INSPECT_LOG_DIR=, as the course says
   it will, is not broken. Apart from the path, the record stream is
   MINOR: =hello.inspect=, =hello.contract= and snapshot =id= are new
   optional keys, and #1, #2 and the escaping are value fixes.

   The hypothesis holds for the stream but not for the file location. Two
   more literal readings to put to the user:
   - "Print numbers that decode to different values" is also in the
     MAJOR row. #1 does exactly that (for example 0.333333333333333 becomes
     0.3333333333333333), and so does escaping for =input.text=. The
     hypothesis treats "closer to the true stack" as a fix. RELEASING.org
     does not say so.
   - The obvious non-breaking route is to keep =.../sicpminus/= as the
     default when =GFORTH_INSPECT_LOG_DIR= is unset. RELEASING.org forbids
     it: "A released file never names a particular downstream project",
     and gate 4 requires =grep -c sicpminus= to print 0. So the options
     are (a) a MAJOR at v0.1.0, which before 1.0 and as the first tag
     costs nothing in numbering; (b) a carve-out in RELEASING.org:
     18ebe2d was never a release, so v0.1.0 is not breaking anything
     released; or (c) a default that names no project but keeps reading
     where the course reads, which is not on the table. This is a decision
     for the user, not for the experiment. inspect.fs was not patched.

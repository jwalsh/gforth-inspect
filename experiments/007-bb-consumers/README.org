#+TITLE: 007 bb-consumers: the reference checker and mock server as Babashka twins
#+DATE: 2026-11-21
#+STARTUP: showall

Status: review. The owner asked for the migration. Experiment 006 (PR
#24) assessed the port of the tooling and listed what babashka does not
hand over; this experiment does the one part 006 left frozen: reference
consumers 2 and 3 (RELEASING.org, "The reference consumers"). =stacks.jq=
is not touched: jq stays.

The swap is only a swap if nobody downstream can tell. So the claim is
value equality with the Python originals on every input in the gate,
quirks included, and the Python originals are the oracle until the gate
passes. They are not edited.

* Hypothesis

The bb twins =pbt/consumers/bb/checker.clj= and
=pbt/consumers/bb/mock_server.clj= produce output equal by value to
=pbt/consumers/checker.py= and =pbt/consumers/mock_server.py= on every
input in the gate below: the same exit status, the same stdout object
(floats compared by bit pattern, numbers by JSON type, so =1= is not
=1.0= and =true= is not =1=), the same crash where the Python crashes
(exception class and message, e.g. =KeyError: 'data'= on a record that
validates but lacks =data=, which 004 records as an output), and for the
server the same status, content type and body bytes.

* Prediction (written before any twin code)

Holds, once four things the twins cannot borrow from bb are built by hand:

- a strict JSON reader that matches Python's =json.loads=, not
  cheshire's: raw control characters rejected, exactly one value per line
  (cheshire returns the first object of ={..}{..}=), =NaN=/=Infinity=
  accepted by the version stop's bare =json.loads= but rejected by the
  last-line parse (=parse_constant=), duplicate keys last-wins at the
  first key's position, integers over 4300 digits rejected (Python's
  =int_max_str_digits=);
- a subset validator with checker.py's eight keywords and its order of
  checks, so the /first/ error and its message are the same, including
  Python's =repr= of lists, strings and floats in the message, and
  Python's equality for =const=/=enum= (=1 == 1.0=, =[True] == [1]=, but a
  bare =True= is not =1=);
- a printer that writes what =json.dumps(..., ensure_ascii=False)= writes,
  =Infinity= for an overflowed number included, and that fails as Python's
  =print= fails on a lone surrogate (=UnicodeEncodeError=, exit 1, empty
  stdout);
- for the server, nothing beyond http-kit: 006 already served a =0xFF=
  line byte for byte.

The likeliest divergences: float printing (Java's =Double.toString= gives
=4.9E-324= where Python gives =5e-324=, the same double), sort order of
extra keys (UTF-16 order is not code point order past the BMP), and
Python's crash messages on odd shapes (=TypeError= for a non-object
=input=). The first is equal by value and is not a divergence; the other
two are, and must be matched.

* Gate (fixed before any twin code; the log appends, never edits this)

Both sides run on the same bytes. The comparison is the twin's output
against the Python's output, live, never against a copy of it; the corpus
is compared both ways.

1. *Corpus.* For every =corpus/NN-slug.jsonl= of PR #22 (taken from the
   tree if =corpus/= is there, else from =origin/feat/corpus=), with the
   schema blob named in its =PROVENANCE=: the bb checker's exit and output
   equal the Python checker's and =NN-slug.expect.json='s =checker=, and
   the bb server's status and body equal the Python server's and the
   file's =mock_get_stacks=. Every scenario, none skipped.
2. *Planted breaks.* The six plants of 004 (=004-rename-data=,
   =004-split-record=, =004-hex-integer=, =004-nan-zero=,
   =004-default-path-empty=, =004-contract-minor=) are applied to harden's
   =inspect.fs= by their own =sed=, a fixed program is run on each, and
   both checkers and both servers see the resulting log: equal outputs.
   Plus the contract-1.2 version stop: a log whose hello announces =1.2=,
   read with the default =--expect= (stop, minor), with =--expect 1.2=
   (accepted), with =--expect 2.0= (stop, major) and with
   =--no-version-stop=: equal outputs on all four.
3. *Unknown keys.* Every record of item 4 is also read with an unknown key
   injected at the top level and inside =input= (004's =_inject=): the
   two sides agree on the injected logs, and each side's output is the
   same as on the plain log.
4. *Generated differential.* At least 500 snapshot records produced by
   =gforth_run= (004's program strategy: data and float stacks, the three
   snapshot paths, input lines of any bytes but LF and CR, so non-UTF-8
   lines are in it), on harden's =inspect.fs=. For each log the checker is
   run on every prefix, with and without the version stop, and also on
   mutated records (each schema keyword the checker implements gets
   records that violate it), and the server is asked for every prefix.
   Lines split across reads: the log is also cut at arbitrary byte
   offsets (mid-record and mid-UTF-8-sequence) and both sides read after
   each cut. Zero disagreements. The default profile stays under about
   three minutes for =gmake -C pbt check=.
5. *Calibration.* Three faults planted in the twins, never in the Python,
   each must make the differential (item 4, or 2 for the version stop) go
   red, by =pbt/calibrate/007-*.sh=:
   (a) a lenient reader: the twin's strict reader replaced with cheshire's
       default =parse-string=;
   (b) a missing schema keyword: the twin's =enum= check removed;
   (c) a version stop that ignores MINOR: the twin compares MAJOR only.
6. *Server bytes.* For a log whose last line holds a =0xFF= byte (and one
   ending without a newline, and an empty one, and a missing file): the
   bb server's status, =Content-Type= and body bytes are identical to the
   Python server's, and the body is the last line byte for byte.

Declared in advance, and only these, as outside the gate: nesting deeper
than 100 levels (Python's =RecursionError= threshold depends on the
interpreter's stack); =-h=/=--help= text; methods other than GET and
request targets other than origin-form paths. And one deliberate
difference: a schema keyword that checker.py neither implements nor is
known to ignore makes the twin refuse to run (exit 2), where checker.py
would silently ignore it. The keywords checker.py ignores that the
contract schema uses (=$schema=, =$id=, =title=, =description=,
=pattern=, =x-*=) are listed in the twin and ignored as checker.py
ignores them, =pattern= included.

* Log

** 2026-11-21 gate committed (07686b4), then the twins

The gate went in at 07686b4, before any twin code. The twins and the
differential followed in one commit (16cfbe6): =pbt/consumers/bb/checker.clj=,
=mock_server.clj=, the harness-only =driver.clj=,
=pbt/test_007_bb_consumers.py= and =pbt/calibrate/007-*.sh=. Nothing outside
babashka is used: cheshire only in the driver's own I/O and in plant (a),
http-kit for the server.

Python behaviour was probed before the twins were written, on Python
3.14.8, and built in rather than found by the gate: Java prints 5e-324 as
=4.9E-324=, so the printer checks whether a one-digit decimal round-trips
and takes it when it does, as Python's repr does. Python's =int_max_str_digits= is
4300, counting digits but not the sign. =print= of a lone surrogate fails
with a =UnicodeEncodeError= whose position is a code point index, and a run
of surrogates is reported as a range. =sorted()= orders keys by code
point, so U+FFFF comes before U+10000; UTF-16 order agrees on that pair
only by luck, so the twin compares code points. =repr= uses double quotes
when the string holds ='= and no ="=. In the validator, =1.0= passes
=const 1= but =true= does not.

Two babashka gaps that cost a redesign, not a divergence: there is no
=java.util.LinkedHashMap= in bb, so a JSON object is a Clojure map whose
metadata holds the key order, with a repeated key keeping its first place
and its last value as in a Python dict. And =AccessDeniedException= is not
exposed as a class, so it is matched by name.

Namespaces (coordinator, from clj-kondo): =pbt/consumers/bb/= is the
source root, so the namespaces are =checker= and =mock-server=, and the
driver requires =checker= through the classpath. =clj-kondo --lint
pbt/consumers/bb= is clean.

Corpus: PR #22 merged while this ran. The test reads =corpus/= from the
tree if it is there, else from =origin/main=.

** 2026-11-21 first runs (gates 1-4, 6)

The first full run of the differential (seed 1) was green, with no
disagreement on any input. So the gate found no divergence the probes had
not already built in. 648 gforth snapshot records, 9165 logs, 11261
checker comparisons, every stdout byte-identical, and 9165 server
comparisons. It took 163 s, 86 s of it in the bb checker. Two speed-ups,
neither changing what is computed: strings are scanned between special
characters with a regex rather than char by char, and the driver runs jobs
with =pmap=. After them: bb checker 22 s, all of 007 in 110 s.

The 004 plants read only the last line at first, so =hex-integer= and
=nan-zero= (which change the =.stacks= record, not the =~~~= one after it)
never reached the checker. The test was changed to read every prefix, as
004 does, before the logged run.

** 2026-11-21 calibration (gate 5)

Each plant edits a temp copy of the twins (=BB_CONSUMERS_DIR=), never the
Python. Seed 7, no shrinking:
- (a) lenient reader: red, =disagree checker: mutation raw-control
  no-stop=. The first version of the plant went red for the wrong reason:
  cheshire returns =java.lang.Integer= for small numbers, which the twin's
  =repr= does not know. The plant now converts cheshire's numbers to the
  twin's types, so it differs from the twin in leniency alone. It is a
  second reason not to use cheshire's reader here.
- (b) no =enum=: red, =disagree checker: mutation enum-event=.
- (c) version stop on MAJOR only: red, =version stop []= (the contract-1.2
  log read with the default =--expect=: the original stops, the plant
  accepts).

** 2026-11-21 decision: what happens to the Python originals

The owner ruled, through the coordinator: the reference checker and mock
server are the bb twins. =checker.py= and =mock_server.py= stay only as
the other side of this differential, until the test runner itself is in
bb (experiment 006 ports =pbt/gforth_run.py= and the harness). They are
deleted in that port's PR, not kept for a release. =stacks.jq= is
unchanged: jq stays. RELEASING.org says this, citing 007.

** 2026-11-21 review (=/code-review high= on PR #28)

Ten findings, none raised by the gate, because every gate input used a
well-formed schema, a plain path and a UTF-8 locale. Each was checked
against the Python before it was answered. Every fix went into the twin,
never the original.
- =//stacks=: http.server collapses leading slashes (CPython gh-87389), so
  =GET //stacks= is a 200 from the original. Confirmed, and the twin now
  collapses them too. =//stacks=, =///stacks= and =//other/stacks= are in
  gate 6's cases.
- Unreadable log paths: java.nio puts the path in front of the reason (and
  says "Too many levels of symbolic links or unable to access attributes
  of symbolic link"). Confirmed for ENOTDIR, ELOOP and ENAMETOOLONG. The
  prefix is now stripped and ELOOP is reworded.
- The schema file: it is now strict UTF-8, and OSErrors are raised with
  Python's class, errno and repr'd path. The errno values are macOS's,
  which is where the gate runs. Still not matched, and outside the gate
  (a broken schema is not a consumer input): the text of a
  =UnicodeDecodeError=, and the position suffix of a =JSONDecodeError=, in
  the schema file.
- argparse: =--expect -= and =--expect -1.1= are values, and =-v= is an
  unknown option. Confirmed, and fixed with argparse's negative-number
  rule.
- Locale: under a C locale or =PYTHONUTF8=1=, Python's stdout uses
  surrogateescape, and =\udc80..\udcff= would print. The reference is
  defined on a UTF-8 locale with strict stdout, which is what =uv run=
  gives here. That is declared scope, not matched. A =\udc80= case is in
  the CLI test.
- Unicode tables: checked. bb's JDK 25.0.4 and Python 3.14.8 are both
  Unicode 16.0 (U+1C89 is Lu on both).
- Annotation keywords (=$comment=, =default=, =examples=, =deprecated=,
  =readOnly=, =writeOnly=) are now ignored, as checker.py ignores them. A
  validation keyword the twin lacks still makes it exit 2. RELEASING.org
  now names that difference.
- Test hygiene: the servers fixture uses an ExitStack. =test_zz_volume=
  skips when the differential did not run. The batch floor was raised to
  6 programs after one default run came in at 503 records, too close to
  the 500 floor.
- Names: the one-letter locals were renamed (a mechanical pass; the string
  literals were diffed before and after, unchanged). =clj-kondo= is clean.

** 2026-11-21 verdict

On the final tree (977eab0 plus docs), =gmake -C pbt check= (default
profile, random seed): 87 passed, 1 xfailed (005's strict xfail), 363 s
for the whole suite. 007 itself took about 80 s.
1. Corpus: *held*. 16 of 16 scenarios, read from =origin/main= (#22): the
   bb checker equals the Python checker and =expect.json=, and the bb
   server equals both.
2. Planted breaks: *held*. The six 004 plants on harden c1a6a3a, every
   prefix, with the stop on and off, give equal outputs. That includes
   =KeyError: 'data'= on rename-data, and =unreadable: No such file or
   directory= on the moved default path. The contract-1.2 stop gives equal
   outputs on all four readings, and the original's answers are pinned.
3. Unknown keys: *held*. No change on either side, for the checker and
   the server.
4. Generated differential: *held*. 818 gforth snapshot records, 9543 logs
   (prefixes, injected, 59 mutations, 13 hello variants x 7 expects, byte
   cuts mid-record and mid-UTF-8), 12110 checker comparisons and 9593
   server comparisons, with 0 disagreements. Every compared stdout was
   byte-identical too (12095 of 12095, past usage errors).
5. Calibration: *held*. Plants (a), (b) and (c) each go red with the
   expected disagreement. =gmake -C pbt calibrate= is red on all 15
   plants.
6. Server bytes: *held*. =0xFF=, a missing final newline, an empty file, a
   missing file, other paths and slash variants all give the same status,
   content type and bytes, and the body is the last line.

The hypothesis held. Divergences found by the gate: none. Divergences
found by review: the six above, all fixed in the twin. Divergences left on
purpose: the exit-2 refusal on an unimplemented schema keyword; the locale
and schema-file error text listed above; and the scope declared in the
gate.

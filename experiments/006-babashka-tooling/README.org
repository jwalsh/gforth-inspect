#+TITLE: 006 babashka-tooling: port the test and dev tooling to Babashka, as a differential
#+DATE: 2026-11-21
#+STARTUP: showall

Status: proposed. Decision 28 in [[file:../../.meta/decisions.org][.meta/decisions.org]]: port after
v0.5.0, as a gated experiment; shell scripts are suspect; the frozen
reference consumers stay as they are. Nothing is ported by this file. It
is the assessment, the gate, and the order of work, written before the
first line of Clojure so that the gate cannot be fitted to the port.

* Hypothesis

The property suite (=pbt/=), its planted-fault calibrations, the corpus
recorder (PR #22) and the repo scripts can be rewritten in Babashka so that
the rewrite is a faithful twin of the Python: red on exactly the same
planted faults, for the same reason, and in agreement with the Python on
every recorded corpus log. After it, Python is left only where it is
frozen (=pbt/consumers/=) or bound to a host API (=lldb/gforth.py=), and
=uv=, =pytest=, =hypothesis= and =jsonschema= leave CI.

* Prediction (written before any port)

- Holds for 002, 004, 005, the scripts and the corpus, at about the same
  wall clock, once three things are built that babashka does not hand
  over: a strict JSON reader (cheshire's defaults accept what the tests
  must reject; measured below), a JSON Schema validator for the subset the
  contract uses (there is none in babashka), and an expected-failure
  marker for 005's strict xfail.
- Weakest at 001. Its float generators are bit patterns. test.check's
  integer generators are size-scaled and its shrinking is signed, so a
  naive port samples the exponent field badly and shrinks a sign fault to
  a NaN (measured below). Faithful only with generators built for it:
  edge list, sign-plus-magnitude tuples, uniform 16-bit chunks, and
  =gen/double= mapped to bits.
- =demo/cast.py= does not port cleanly: babashka has no pty. =script(1)=
  gives the child one and bb can timestamp its output (checked on macOS),
  but that is BSD =script= syntax. Predicted outcome: cast.py stays, or is
  replaced with a macOS-only bb task, owner's call.
- Python cannot leave the repository entirely, and the hypothesis does not
  claim it: the release gate runs the frozen =checker.py= and
  =mock_server.py=, and a bb twin of either is an addition, never a
  replacement (RELEASING.org: a changed reference consumer is a breaking
  change).

* Gate (fixed now; a port PR appends to the log and never edits this)

The Python suite is the oracle until the gate passes. Both suites run, on
the same inspect.fs blob, in the same CI job, for as long as the port is
in review.

1. *Planted-fault parity.* For every plant in =pbt/calibrate/= (12 on
   main, plus 005's once #18 lands): the plant is applied once, by the
   existing =sed=, and the planted file is handed to both suites, so the
   two never test different bytes. Both go red. The set of failing test
   ids is the same after normalisation (=test_p1_noninterference[dotstacks-gforth]=
   and =p1-noninterference--dotstacks--gforth= are one id), and the
   failure class is the same: P1 data/float, P2 float
   sign/precision/non-finite, =[json]=/=[text]=,
   =breaking consumer=X field=Y=. A plant that goes red in one suite only
   is a refutation of the hypothesis for that experiment.
2. *Clean parity.* On harden's head (pinned by hash in the log), both
   suites are green on all three engines, at the default profile and at
   the =ci= profile (1000 examples), at three logged seeds each.
3. *Corpus agreement.* With PR #22 merged: for every
   =corpus/NN-slug.jsonl=, the bb side's strict parse, schema verdict and
   extracted fields equal what =corpus/NN-slug.expect.json= records.
   Compared as values, floats by bit pattern, never as bytes: cheshire
   prints =1e16= as =1.0E16= and Python as =1e+16=, the same double. If
   =record.py= is ported, its =.jsonl= output is byte-identical (it is raw
   gforth output with =t= masked) and its =.expect.json= equal as values.
4. *Strict-JSON parity, by call site.* A table of lines (below, plus
   =test/contract/bad.jsonl= on harden and one line from each 002 invalid
   class) is read by each Python call site and by its bb replacement, and
   they accept and reject the same lines. Divergences that are declared
   here in advance, and only these, are allowed: bb rejects =NaN= and
   =Infinity= at call sites where Python's bare =json.loads= accepts them.
5. *The differential is itself calibrated.* Three faults are planted in
   the port, never in the Python, and items 1, 3 and 4 must go red on them:
   (a) the bb reader built with cheshire's default factory (unescaped
   controls accepted); (b) the float comparison in the 001 port done with
   ~=~ on doubles instead of bit patterns; (c) one of 001's three paths
   dropped from the generated tests.
6. *Shrink quality, 001.* For plants 001-a, -b and -c, over five seeds:
   the bb counterexample replays the fault through its one-line
   =gforth inspect.fs -e '...'= reproducer, and its median size (cases in
   the batch, data depth, float depth) is at most twice the Python
   counterexample's. A worse result is logged, not hidden; it is a
   refutation of the 001 part only.
7. *Cost.* =gmake -C pbt check= wall clock on the bb side within 1.5x of
   the Python side on the same machine, default profile. CI install of bb
   measured on the macOS runner and logged (not yet measured; see CI).
8. *Retirement.* Python's test is removed experiment by experiment, only
   after 1 to 6 hold for that experiment, by its own PR. =uv= leaves
   =verify.yml= only when the last ported experiment is retired.

** Shrinking on 001's bit patterns

Three properties that fail on part of the float space, five seeds, 2000
trials, the same in both libraries. Rows are properties, columns generators.

| property fails when   | Hypothesis =integers(0,2^64-1)= | test.check =gen/large-integer= as bits | test.check sign + 63-bit tuple | Hypothesis =floats().map(bits)= | test.check =gen/double= to bits |
|-----------------------+---------------------------------+----------------------------------------+--------------------------------+---------------------------------+---------------------------------|
| sign bit set          | =0x8000000000000000= (-0.0), 5/5 | =0xFFFFFFFFFFFFFFFF=, a NaN, 5/5        | =0x8000000000000000=, 5/5       | =0x8000000000000000=, 5/5        | =0xBFF0000000000000= (-1.0), 5/5 |

| =%.15g= loses the value | subnormals 1.06e-309 to 1.41e-309, 5/5 | subnormal or -DBL_MAX, 722 to 1982 shrink nodes | subnormal 1.0e-309, 599 to 1658 nodes | =1000000000000001.0=, 5/5 | =1.000030517578125=, 64 to 109 nodes |

Coverage, measured over 2000 values drawn at quick-check's sizes:
=large-integer* {:min 0}= gave 0 patterns with an all-ones exponent and
225 with a normal exponent at all; =gen/large-integer= gave 904 all-ones
exponents, nearly all from small negatives, which are NaNs; four
=gen/choose 0 0xFFFF= chunks gave 2000 normal exponents and 1 all-ones.
So the port's =float_bits= is a =gen/one-of= of the edge list, a
sign-plus-mantissa tuple (subnormals), uniform chunks, and =gen/double=
mapped to bits: the same four arms as 001's, each built for test.check.
Every shrink node in the real suite is a gforth run; 2000 nodes at a few
tens of milliseconds is a minute per failure, which is why gate 6 exists.

* Shell: what moves and what stays

The house rule, from the babashka workshops, is /Babashka, not Python/
for scripting, and the incidents behind it are about logic in shell, not
about shell as glue. Two of them, in the public spectre workshop's
=.meta/findings.md=: 64, zsh did not split =$a= into words and three
flagged names were saved as one argument; 65, a name flattened by
=LC_ALL=C tr= (bytes) and by bb (characters) came out different, so one
function now answers for both. The workshops' own Makefiles keep shell in
recipes for tmux, Emacs and process glue. The rule applied here: a script
that parses, loops over files or holds a table of plants is a bb task;
a script that only starts programs in a terminal stays shell.

Local incident, found by this assessment and not fixed here:
=scripts/privacy-scan.sh= builds its file list with
=set -- $(git ls-files ...)=, so a tracked file whose name has a space is
split into words, both words fail to open, =2>/dev/null= hides it, and
the scan says =clean=. Reproduced in a scratch repository: a file named
=design notes.org= holding a home-directory path, scan exit 0, "clean (3
files)" for two files. No tracked file has a space in its name today
(=git ls-files | grep -c ' '= is 0), so the scan has not missed anything
yet. A name that is a glob is expanded instead. This is the shape of
finding 64, in the gate that decision 3 rests on.

* Risks

- /Shrinking on bit patterns/ (001). Measured above: a signed generator
  shrinks a sign fault to a NaN, and a size-scaled one never reaches the
  exponent field. The built generator answers coverage; gate 6 answers
  whether its counterexamples are as useful.
- /A lenient reader passing for a strict one./ cheshire's defaults accept
  a raw control character and the first object of a torn line, exactly the
  two things 002 and 005 exist to catch. A port that called
  =json/parse-string= would go green on harden's head and on several
  plants. Gate 5(a) plants that port on purpose.
- /One validator where there were two./ The subset validator replaces a
  third-party one; a bug in it and the same bug in =checker.py='s subset
  would agree. Keep a jsonschema run over the corpus, or run that check on
  the JVM, until a second validator exists.
- /Calibration coupled to pytest./ Every calibration script reads pytest
  output. If the bb runner's ids or messages differ, a plant can look
  caught for the wrong reason. Gate 1 compares normalised ids and classes,
  not text.
- /Comparing printed forms./ Python and cheshire print the same double
  differently. Anything that diffs JSON as bytes across the two will
  report differences that are not there. Compare values, as gate 3 says.
- /Numeric equality./ Clojure's ~=~ says =1= and =1.0= differ; Python's
  ~==~ says they are equal, and that =True == 1=. Every comparison in the
  port says which it means.

* Hypothesis

The default log directory of 0.3.0 (=contract/stacks-log.org=, "Files")
maps every project to =<base>/<owner>/<repo>/<worktree>= such that each
component is one safe path component (P1), the same name always gives the
same component (P2), different names never share one, also after
case-folding (P3), and =inspect.fs= computes exactly what the Python
reference in =stacks-log.org= computes, on real fixture trees (P4).

* Prediction

P1-P4 hold for every branch name =git check-ref-format --branch= accepts,
for arbitrary owner and repo bytes, and for every accepted url form; each
of eight planted faults turns P4 red, and the faults that break safety or
injectivity also turn P1 or P3 red.

* Gate

1. =pbt/test_011_log_paths.py= green under =gmake -C pbt check= (100
   examples a property; =PROFILE=ci= 1000), on the working tree's
   =inspect.fs= (=gmake verify=).
2. Branch names come from a wide generator (Unicode, =/=, =.=, =@=, ={=,
   control characters, names up to 300 bytes) and are kept only when real
   git accepts them.
3. =gmake -C pbt calibrate=: every =pbt/calibrate/011-*.sh= red.
4. Every gforth run has its own temp dir as =HOME=, =XDG_STATE_HOME= and
   cwd (E-10, #46); the driver only computes paths, nothing is logged.
5. Pin-on-find: each shrunk counterexample becomes an =@example=.

* Log

** 2026-11-22 first runs (inspect.fs 0.3.0, working tree)

=pytest test_011_log_paths.py=: 9 passed, 64 s (default profile), all
three engines drawn per example.  Two counterexamples on the way, both in
the harness, neither in the rule:

- a directory named CR: the first driver read the =$PWD= list with
  =read-line=, which also ends a line at CR, so gforth saw the parent.  The
  driver now reads NUL-terminated =$PWD=s with =slurp-file=.  Pinned as an
  =@example= of =test_forth_matches_reference=.
- APFS refuses some names (=EILSEQ=, e.g. U+1CC00): the fixture is
  rejected, not failed, and directory names are drawn from the BMP.

Mutation table (=pbt/calibrate/011-*.sh=, 25 examples each, no shrinking):

| fault                                    | script                  | red    |
|------------------------------------------+-------------------------+--------|
| =/= passed through a slug                  | 011-slash-passes.sh     | P4 P1  |
| no ASCII lowercasing                     | 011-no-lowercase.sh     | P4     |
| no hash (slug only)                      | 011-no-hash.sh          | P4 P3  |
| hash over the slug, not the name         | 011-hash-of-slug.sh     | P4 P3  |
| wrong FNV prime                          | 011-fnv-prime.sh        | P4     |
| FNV truncated to 32 bits                 | 011-fnv-32bit.sh        | P4 P3  |
| leading =.= not stripped                   | 011-no-dot-strip.sh     | P4     |
| =~= allowed in a plain name                | 011-tilde-plain.sh      | P4     |

32-bit truncation also breaks P3: the component shows the top 48 of 64
bits, of which only 16 then carry hash, so collisions come within a batch.
